# Test vectors

QR / payload test vectors for exercising the seedmix scanner.

Everything here is generated by [`../../scripts/gen_vectors.py`](../../scripts/gen_vectors.py):

```
python scripts/gen_vectors.py
```

(Requires `segno` and `pillow`)

## Layout

### `psbt/`

Bitcoin PSBT vectors collected from Blockchain Commons
(BCR-2020-006 / keytool-cli; see `psbt.json` for source URLs).

| dir      | contents |
|----------|----------|
| `raw/`   | raw PSBT bytes: `<slug>.hex` and `<slug>.base64` |
| `ur/`    | Blockchain Commons URs: `<slug>.v2.ur` (`ur:psbt`), `<slug>.v1.ur` (`ur:crypto-psbt`), `<slug>.multipart.ur` (one `ur:psbt/N-M/...` part per line) |
| `qr-png/`| QR PNGs: `<slug>.v2.png`, `<slug>.v1.png`, and `<slug>.part-NN.png` for each multipart part |
| `qr-gif/`| `<slug>.multipart.gif` — animated QR cycling through the multipart parts |
| `qr-jpg/`| `<slug>.v2.jpg` (baseline, subsampled), `<slug>.v2.gray.jpg` (grayscale) and `<slug>.v2.progressive.jpg` (progressive, which TJpgDec rejects) |

The GIF is the file form of the animated multi-part UR: `seedmix_gif_tests`
decodes it frame by frame with the desktop GIF decoder and feeds the QR codes
it reads back into the multi-part UR decoder, so the reassembled PSBT must
match `raw/<slug>.hex` again.

The JPEGs are rendered at a smaller scale than the PNGs (they are the lossy
format, so keeping them small matters more than pixel fidelity):
`seedmix_jpeg_tests` decodes each one with the LVGL decoder the HAL uses and
checks it yields the same QR payload as the PNG of the same slug - for the
dense `keytool` single-part QR both formats fail the same way, which is a quirc
limit rather than a decoding one (see below).

### `seedqr/`

SeedQR vectors in the SeedSigner format (`docs/seed_qr/README.md`).

| dir      | contents |
|----------|----------|
| `raw/`   | `<slug>.compact.bin` (raw 16/32-byte entropy = CompactSeedQR), `<slug>.standard.txt` (48/96 BIP-39 index digits = Standard SeedQR), `<slug>.mnemonic.txt` (the mnemonic, for reference) |
| `qr-png/`| `<slug>.compact.png` and `<slug>.standard.png` |

`bip39_english.txt` is the BIP-39 English word list used to derive the
Standard SeedQR digit streams.

### `descriptor/`

Wallet output descriptor vectors, with the same descriptors encoded as
Blockchain Commons URs (BCR-2023-010 `ur:output-descriptor`, tag 40308; and the
legacy BCR-2020-010 `ur:crypto-output`, tag 308). The UR CBOR is written here
from scratch (CBOR + minimal Bytewords + CRC-32) rather than copied.

| dir      | contents |
|----------|----------|
| `raw/`   | `<slug>.txt` — descriptor text |
| `ur/`    | `<slug>.output-descriptor.ur` (BCR-2023-010) and `<slug>.crypto-output.ur` (BCR-2020-010) |
| `qr-png/`| `<slug>.output-descriptor.png` and `<slug>.crypto-output.png` |

Slugs: `wpkh-static`, `sh-wpkh-static`, `pkh-xpub-range`, `pkh-pair-range`,
`sh-multi-static`, `wsh-sortedmulti-static`, `tr-static`.

Only single-part URs are generated (no `qr-gif/`, no multipart `.ur`): every
vector fits in one QR. Multipart/fountain descriptor decoding is covered by
synthetic part builders in `tests/test_ur_descriptor.c`.

### `gif/`

Hand-sized GIFs for the desktop decoder (`platform/linux/gif_gray.c`), one file
per feature it has to get right.  They are 2×2 to 4×4 pixels so the C test can
check every single pixel against a hand-written expectation, and the two
disposal fixtures and the broken ones are packed byte by byte in
`scripts/gen_vectors.py` (Pillow reorders palettes and rewrites frame indices
when it saves, which makes it impossible to pin down which colour a disposal
restores to).

| file | what it pins |
|------|--------------|
| `plain.gif` | a two-frame animation: frame 2 replaces the canvas |
| `disposal2.gif` | disposal 2 (restore to background) and a transparent frame |
| `disposal3.gif` | disposal 3 (restore to previous frame) |
| `interlaced.gif` | the interlaced row order (stored rows 0,1,2,3 shown as 0,2,1,3) |
| `broken-padding.gif` | a stray padding byte before a frame: still decodes |
| `broken-no-trailer.gif` | both frames, then the file ends without `0x3B` |
| `broken-bad-block.gif` | a block byte that is neither extension nor frame |
| `broken-comment-subblocks.gif` | a sub-block longer than the rest of the file |
| `broken-gce-size.gif` | graphic control extension with the wrong block size |
| `broken-truncated-data.gif` | the first frame fits, the file is cut before the second |
| `broken-short-header.gif` | 10 bytes: refused |
| `broken-truncated-palette.gif` | 20 bytes: colour table cut short, refused |

Pillow reads all of these the same way the decoder does, except
`broken-truncated-data.gif`, which it also rejects (`index out of range`) - the
decoder reports the one frame it can still get out of the file and then fails,
which is the behaviour `seedmix_gif_tests` pins.

### `bmp/`

Two 8×8 BMPs for the LVGL-backed decoder (`platform/linux/lvgl_gray.c`), which
is the only decoder that reports the file's own colour depth: LVGL's BMP
decoder hands back RGB565 for 16 bpp and ARGB8888 for 32 bpp, and the JPEG
vectors only ever exercise 24 bpp (RGB888).  Both files have a black top row
and eight colour stripes below it, so the per-pixel luminance and the bottom-up
row order are both checked.  Written byte by byte in `scripts/gen_vectors.py`
because Pillow cannot save 16- or 32-bit BMPs.

### `png/`

PNGs for the desktop decoder (`platform/linux/png_gray.c`), which is what every
screenshot and every "save this QR" button produces.  All of them are 4 pixels
wide (so the packed rows of the 1/2/4-bit images straddle byte boundaries) and
packed byte by byte in `scripts/gen_vectors.py`, which then reads each one back
with Pillow and compares the pixels - a second, independent decoder is what
catches a mistake in the packing or in the row filters.  Pillow gets the
filtering wrong nowhere but cannot *write* these: 16-bit and 1/2/4-bit images,
a chosen filter per row, and fields that are deliberately invalid.

| group | files | what they pin |
|-------|-------|---------------|
| grayscale | `gray-{1,2,4,8,16}bit.png` | all five depths, including the sub-byte sample packing and the byte scaling (1-bit 0/255, 2-bit steps of 85, 4-bit steps of 17) |
| colour | `rgb-{8,16}bit.png`, `rgba-{8,16}bit.png` | three- and four-channel rows, high byte of a 16-bit sample |
| alpha | `gray-alpha-{8,16}bit.png`, `rgba-alpha-{8,16}bit.png`, `palette-alpha.png` | compositing over white: black at alpha 0 stays white, alpha 128 gives 127 |
| palette | `palette-{1,2,4,8}bit.png` | palette indexes at all four depths, and a `tRNS` alpha table |
| filters | `filters.png` | one row per filter type (none, sub, up, average, paeth) |
| interlaced | `adam7-gray-8bit.png`, `adam7-rgba-16bit.png`, `adam7-1x1.png` | Adam7 passes, and the sizes where most passes stay empty |
| edges | `wide-16x1-1bit.png`, `tiny-1x1.png` | a row that is not a whole number of bytes, and the smallest image |
| broken | `broken-*.png` | the signature, a chunk CRC, truncation, a chunk length running past the file, an IHDR that is not 13 bytes, a second-rate colour type/depth/interlace, zero and absurd sizes, no IHDR, no IDAT, no PLTE, a PLTE that is not whole RGB triples, scanlines shorter and longer than the header promises, filter type 5, and a palette index past the end of the table (which renders the pixel black rather than failing the image) |

The invalid-field fixtures carry **correct CRCs**: otherwise the file would be
rejected before the field is ever looked at, and the test would pass without
testing what it says.  `broken-crc.png` covers the CRC path on its own.

## C test suite

The payloads here are also consumed by the C unit tests at runtime:
`seedmix_ur_tests` decodes each PSBT's hex, v1/v2 UR and multipart parts,
`seedmix_seedqr_tests` round-trips every SeedQR compact/standard vector against
the reference mnemonic, `seedmix_gif_tests` decodes the `qr-gif/` animations
frame by frame and reassembles their multipart PSBTs (and checks the `gif/`
fixtures pixel by pixel), `seedmix_png_tests` decodes every `qr-png/` and
`seedqr/qr-png/` vector plus the `png/` fixtures pixel by pixel, and
`seedmix_jpeg_tests` decodes the `qr-jpg/` vectors against the UR text of the
same QR and checks the `bmp/` fixtures pixel by pixel, and
`seedmix_descriptor_tests` decodes every
descriptor vector's `output-descriptor`/`crypto-output` UR and checks the
result is address-equivalent to the `raw/` text. The vectors directory is
passed in as `TEST_VECTORS_DIR` (see `tests/CMakeLists.txt`), so regenerate
with `python scripts/gen_vectors.py` before running the tests.

## QR codes quirc cannot read

`keytool-cli-…-1-in-2-out` has a single-part UR long enough for a QR version 30
code: 39 finder + alignment patterns, where quirc's identifier stops at
`QUIRC_MAX_CAPSTONES` (32), i.e. around version 26.  Neither the PNG nor the
JPEG of that code decodes - from a file *or* from the camera - which is what
the animated multi-part form is for: one small QR code per part.  The vector is
kept because `seedmix_jpeg_tests` pins exactly that behaviour, including that
its first multipart part still reads.
